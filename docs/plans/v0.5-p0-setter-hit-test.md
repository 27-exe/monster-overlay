# v0.5 P0 — Panel setters + HudCanvas toggle + hit-test

## Goal

Wire the next layer of control console features by adding the setters
and signals the UI needs but doesn't have yet. No UI work in this pass —
only the API surface, plus the small bits of glue that make the new
methods verifiable.

## Context

The v0.5 console was committed in `a3b6a2b`. It exposes the panels'
geometry as **read-only** getters on `Panel` (`corner()`, `margins()`,
`scale()`) and a `PanelSource` get-only interface that the canvas binds
to. Two follow-up UI directions are blocked until the panels support
**being written to**:

- **Appearance fold** — scale slider (HTML `v0.5-A` spec §APPEARANCE).
  User-visible value is currently `Panel::scale()` only; setting it
  requires a `setScale(qreal)` that actually resizes the layer-shell
  surface and persists.
- **Opacity slider** — same shape, `setOpacity(qreal)`.
- **Reset current panel** — `Panel::resetToDefaults()` restoring
  section mask, scale, opacity, and margins to factory values.

The canvas also needs two pieces of state that are currently always-on:

- **Safe area** dashed rectangle — toggleable for screenshot capture.
- **Grid crosshair** at the centre — toggleable for alignment work.
- **Click-to-select** — clicking a panel in the canvas should
  propagate the selection up to the control console so the inspector
  switches. This is the foundation of the "canvas is the workbench"
  metaphor.

## 1. `Panel::setScale(qreal)`

```cpp
// panel.h (public)
void setScale(qreal s);
// panel.h (private helper)
void applyScale();
```

Behaviour:
- Clamp `s` into `[kMinScale, kMaxScale]`.
- If unchanged, return.
- Store, then `applyScale()`:
  - If `logicalSize_` is valid, call `setContentSize(logicalSize_.width(), logicalSize_.height())` — that helper already re-derives the actual window size from `logicalSize_ * scale_` and re-issues the layer-shell desired size.
- `update()`.
- Persist: `saveConfig()` only when called in **edit mode** (matches the
  existing `wheelEvent` policy; live mode never pays the save cost).
  Add a `bool persist` parameter (default `true`) so the canvas can
  call `setScale` while rendering without hitting disk.

Tests:
- `setScale` from 1.0 to 2.0 changes `size()` to `2 × logicalSize_`.
- `setScale` from 1.0 to 1.0 is a no-op (no update()).
- `setScale(0.1)` clamps to 0.5.
- `setScale(10.0)` clamps to 3.0.

## 2. `Panel::setOpacity(qreal)`

```cpp
// panel.h (public)
void setOpacity(qreal a);
```

Behaviour:
- Clamp into `[0.1, 1.0]`.
- `setWindowOpacity(clamped)`.
- Persist (`saveConfig()`) only in edit mode, same rule as `setScale`.

Tests:
- `setOpacity` with arbitrary value lands in `[0.1, 1.0]`.
- `setWindowOpacity` is called with the clamped value.

## 3. `Panel::resetToDefaults()`

```cpp
// panel.h (public)
void resetToDefaults();
```

Behaviour:
- Mask → `0xFFFFFFFFu` (all sections visible).
- Margins → `defaultMarginsFor(corner_)`.
- Scale → `1.0`.
- Opacity → `0.85` (the in-code default from the constructor).
- `applyScale()` to re-sync the widget size.
- `setWindowOpacity(opacity_)`.
- `update()`.
- `saveConfig()` (always — this is an explicit user action and the
  cost is one QSettings write).

Tests:
- After `resetToDefaults()`, `sectionMask() == 0xFFFFFFFFu`, `scale() == 1.0`, `opacity() == 0.85`, `margins() == defaultMarginsFor(corner_)`.

## 4. `HudCanvas::setShowSafeArea(bool)` / `setShowGrid(bool)`

```cpp
// hud_canvas.h (public)
void setShowSafeArea(bool on);
void setShowGrid(bool on);
bool showSafeArea() const { return showSafeArea_; }
bool showGrid() const { return showGrid_; }
```

Default both to `true` (matches the current behaviour).

`paintEvent` honors the toggles:
- Skip the safe-area dashed rectangle when `!showSafeArea_`.
- Skip the crosshair lines when `!showGrid_`.

Tests:
- After `setShowSafeArea(false)`, the safe-area rectangle is not drawn.
- After `setShowGrid(false)`, the crosshair lines are not drawn.

## 5. `HudCanvas::panelSelected(int)` signal + mousePressEvent

```cpp
// hud_canvas.h
signals:
    void panelSelected(int index);
protected:
    void mousePressEvent(QMouseEvent *e) override;

// hud_canvas.cpp
void HudCanvas::mousePressEvent(QMouseEvent *e)
{
    if (e->button() != Qt::LeftButton) return;
    // Hit-test the three bound slot rects in their canvas coords.
    // Use the same `logicalToCanvas` map that paintEvent uses, but
    // compute positions up front so we don't tangle with the paint
    // path. Cache the three target rects in the `Slot` struct as a
    // `QRectF lastTarget_` field updated at the end of paintEvent.
    for (int i = 0; i < 3; ++i) {
        if (!slots_[i].bound) continue;
        if (slots_[i].lastTarget_.contains(e->pos())) {
            emit panelSelected(i);
            setSelectedPanel(i);   // also update the visual ring
            e->accept();
            return;
        }
    }
}
```

Add `QRectF lastTarget_` to `Slot`. After computing each `target`
in `paintEvent`, store it. On `_` reset (repaint → next call), zero
the field so the hit-test only fires when the canvas has been painted
at least once.

Tests:
- Clicking inside the player panel rect emits `panelSelected(0)`.
- Clicking outside any panel rect does not emit the signal.
- `setSelectedPanel` still works the same way (existing behaviour).
