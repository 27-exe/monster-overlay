# Monster Overlay i18n 规范

> 本文是 monster-overlay 界面多语言适配的**唯一规范**。`src/ui/panel_player.cpp`、
> `src/ui/panel_monster.cpp`、`src/rise/reframework/rise_reframework_manager.cpp`
> 的注释引用此文件；改动 i18n 行为前先读这里，改完把规则同步回来。
>
> 状态：v0.11.2。四域划分与三道门禁已落地并接入 ctest。未决：`overlay.json`
> 的 45 个 key 尚未收敩到三层命名；`data.mantle.*` 的 21 个 key 因 `mantleName()`
> 运行时拼 key 而被 `unused` 误判为死键，`--strict` 目前是红的（见 §7）。

## 1. 运行时机制

`mhw::StringTable`（`src/core/string_table.h`）是唯一入口：

- 每个 locale 是一个 qrc **目录**：`:/i18n/<locale>/<domain>.json`
- `load(locale)` 把该目录下所有 `*.json` 合并成一张扁平表；同名 key 后者胜
- `tr(key)` 查不到时**返回 key 本身**，让缺失在开发期可见而不是渲染空白
- 已加载的 locale `startsWith("en")` → `isEnglish()` 为真，数据名表据此选英文列
- 运行时热切换：`load()` 可随时用另一个 locale 再调一次，表原地替换；
  缓存了字符串的 widget 必须重新查询 —— 控制台走
  `ControlPanel::retranslateUi()`，overlay 走 conf 轮询（`src/core/locale_sync.h`）

```cpp
mh::tr("console.rail.start_overlay")                              // 取文案
mh::tr("ui.player_connected").arg(cur).arg(max)                   // 带占位符
```

## 2. 域文件划分

切分依据不是「哪个进程用」，而是**「谁负责重绘」**——这才是运行时语言切换的正确分组。

| 域文件 | 顶层前缀 | 内容 | 重放机制 | 状态 |
|---|---|---|---|---|
| `overlay.json` | `ui.*` | overlay 面板 chrome（`ui.player_*` / `ui.monster_*` / `ui.zone_*` …） | 各面板 `paintPanel()` 每次重绘重新 `tr()` | ✅ |
| `console.json` | `console.*` | 控制台 chrome | `ControlPanel::retranslateUi()` 重放注册表 | ✅ |
| `reader.json` | `reader.*` | reader 状态 / 诊断上屏文案 | snapshot `status` 每 poll tick 自然刷新 | ✅ |
| `data.json` | `data.*` | 数据名与演示数据（`data.mantle.*` / `ui.demo.*`） | 数据名每次 paint 重新查 | ✅ |

四个域各一个文件、每侧 locale 一套，共 8 个 JSON。**key 命名尚未收敩到
`<域>.<模块>.<语义>` 三层**：`overlay.json` 的 45 个 key 里 38 个是顶层
snake_case（`ui.player_title`，不带中间模块层），只有 `quest_state.*` 7 个
有两层；`reader.json` 的 14 个非 REFramework key 同样是顶层
（`reader.ptrace_denied`）。改名批次未做，§3 的目标形态
**不是**当前全貌——按现状写代码即可，不要为了凑三层去改已有 key。

各域 key 数实测（`i18n_key_parity.py` 输出，zh 与 en 逐域相等）：

| 域 | 顶层对象 | key 数 | 说明 |
|---|---|---|---|
| `console.json` | `console` | 154 | 分组：`reframework` 51、`section` 20、`inspector` 17、`rail` 12、`nav` 8、`canvas` 7、`detect` 6、`panel` 6、`status` 5、`corner` 5、`edit` 4、`locale` 3、`theme` 2、`game` 2、`stage` 2、其余单键 |
| `overlay.json` | `ui` | 45 | 38 个顶层 snake_case 单键 + `quest_state.*` 7 个；中间层只有这一个 |
| `reader.json` | `reader` | 144 | `reader.reframework.*` 130 + 非 REFramework 状态 14 |
| `data.json` | `data` | 56 | `demo.*` 35（console 舞台预览种子）+ `mantle.*` 21（误判死键，见 §7） |
| **合计** | | **399** | 两侧 locale 恒等 |

## 3. Key 命名规范

三层，`<域>.<模块>.<语义>`，leaf 一律 snake_case：

```
overlay.panel.player.header        console.rail.start_overlay
overlay.panel.damage.title         console.section.player.conn
overlay.canvas.hint.unknown        data.mantle.id.3
```

**规则**
- 目标三层；leaf 不缩写、不用 camelCase
- 占位符用 `%1..%N`，且同一 key 的 zh/en **占位符集合必须相同**（`i18n_key_parity.py` 校验）
- `_meta` 只放给维护者看的说明，不进扁平表
- ❌ 不要把非文案塞进来：字体族名、配置键、app 名（`"Monster Overlay"` 由
  `QApplication::setApplicationName()` 承担，不属于翻译表）

## 4. 哪些文本进 i18n，哪些不进

| 类别 | 处置 | 例子 |
|---|---|---|
| UI chrome（按钮、标题、tooltip、状态行） | 必须进 JSON | `console.rail.start_overlay` |
| reader 上屏状态 / 诊断信息 | 必须进 JSON（`reader` 域） | `reader.ptrace_denied` |
| 游戏数据名（怪物 / 部位 / 异常 / 区域） | **留在 C++ 表**，双列 zh/en，运行时按 `isEnglish()` 选列 | `kRiseAilmentNames`、`zoneNameLocalized()` |
| 人工语义决策的别名 | 进 `data.json` | `mantle.*` / `abnormality.*` |
| 演示数据（snap_*、console 舞台预览） | 进 `data.json` 的 `ui.demo.*` | |

**为什么数据名表不搬 JSON**：它们是 HunterPie Localization XML 生成的编译期
`constexpr` 表，带 sha256 溯源链；量大、不可手译，搬进 JSON 只会丢掉
编译期校验。需要第三语言时按同一生成器补一列即可。

**判断一个 tag 归属的方法**：问「这是 UI 结构的一部分，还是这个数据的固有属性？」
前者进 `overlay`/`console` 域走 `tr()`，后者留在数据表按列选。

## 5. 兜底策略

### UI 层：**代码里不允许兜底**（no fallback in code）

key 必然存在（`i18n_key_parity.py` 保证 zh/en 对齐），所以 UI 层的
`kFallback` 数组是死码，还会把「切语言后标签不变」的 bug 藏起来——
`static const QStringList` 会把首次使用的语言冻结。UI 层一律直接 `tr()`。

### 数据层：允许成对出现

`kFoo` 表的 `{name, nameEn}` 是数据，不是文案兜底。en 列为空时读 zh，
这是「数据缺英文译名」的合理降级，不是 i18n 漏洞。

### 唯一例外：拿 `tr()` 结果做相等比较的哨兵

一处 key 缺失的哨兵比较会带一个 ASCII 兜底文案。当前共四处，改动时必须连同相关一起看：

- `src/core/string_table.h:83` — `mantleName()`，缺失时回落 `"Mantle #%1"`
- `src/core/game_capabilities.cpp:84` — `gameDisplayName()`，缺失时回落 traits 表的
  ASCII 列（`WORLD` / `RISE`）；**这就是 `console.game.world` / `console.game.rise`
  的取值路径，见 §6**
- `src/ui/hud_canvas.cpp:80` — `panelName()`，缺失时回落面板 ASCII 名
- `src/ui/hud_canvas.cpp:138` — `cornerLabel()` 的未知分支，缺失时回落 `"UNKNOWN"`

（`src/ui/panel_sections.h` 的 `displayName()` 也曾用哨兵，现已改为无条件
`tr()`，不再属于本类。）

## 6. `console.game.*` 是 traits 表的数据列

控制台 GAME 列与自动检测徽标上的游戏名，**不再是**散落的三元表达式，
而是 `src/core/game_capabilities.cpp` 的 traits 表中的一列：

```cpp
struct GameTraits {
    const char *displayNameKey;      // i18n key —— "console.game.world" / "console.game.rise"
    const char *displayNameAscii;    // key 缺失时的 ASCII 兜底
    bool normalisedPartGauges;
    float staminaDivisor;
};
```

要点：

- key 只是**表里的一列数据**，不是某个 `if (game == Rise)` 分支。JSON 里
  `console.game.{world,rise}` 两个字符串照常按 §4 规矩翻译。
- `gameDisplayName()` 先用 `StringTable::tr(key)` 查表，命中就用译文；
  只有 key 缺失（那才是 bug）才回落 ASCII 列。§5 列的四处哨兵之一就在这里。
- 同一张 traits 表还承载 `usesNormalisedPartGauges()` 与
  `staminaDisplayScale()`（Rise 的耐力值除以 30，World 不除）。
- 加游戏是在这张表**加一行**，不是在 UI 里加一个分支——这是这条设计的全部意义。

## 7. 门禁脚本

三个门禁已接入 ctest（`ctest --test-dir build -R i18n-gate`，Test #47/#48/#49），
统一入口 `scripts/i18n_gate.py`：

| 脚本 | 校验 | 默认是门禁？ | ctest 用例 |
|---|---|---|---|
| `scripts/i18n_check_tr_keys.py` | 代码里所有 key 都在 JSON 里有定义 | 是 | `i18n-gate-check` |
| `scripts/i18n_key_parity.py` | zh/en key 集合一致（含 `_meta`、占位符数量） | 是 | `i18n-gate-parity` |
| `scripts/i18n_unused_keys.py` | 报告没人引用的死键 | 否（`--strict` 才门禁） | `i18n-gate-unused` |

单独跑：

```bash
python3 scripts/i18n_gate.py            # 三个都跑，普通模式
python3 scripts/i18n_gate.py --strict   # 死键也当作失败
python3 scripts/i18n_gate.py parity     # 只跑一个
python3 scripts/i18n_gate.py --list     # 打印何时跑哪个的表
```

`unused` 默认只报告、exit 0：一个没人引用的 key 玩家看不见，拿它当门禁会把
一次 cosmetic 清理变成每次提交的红灯。**但当前这棵树 `--strict` 是红的**
（21 个 `data.mantle.*` 被误判，见下），所以发版前跑它之前先看误判清单。

**脚本覆盖范围（改 key 前必须知道）**：`i18n_check_tr_keys.py` 识别
`mh::tr` / `trMessage` / `trVm` / `table.tr` / `instance().tr` /
`trSet` / `trTip` / `trHook` / `trWindowTitle`，含三元分支里的 key 与
`kKeys[]` / `kCorners` 这类静态数组初始式里的字面量（数组名须带
`keys`/`corners`/`names` 字样，否则会被当作格式串放过）。
`src/core/string_table.h` 被排除——它的 schema 示例是注释不是调用点。
**仍然抓不到**：`consoleText(stateKey)` 这类由变量拼出的 key、以及不带上述
命名的静态数组。

**已知盲区，实测**：`i18n_unused_keys.py` 目前报 21 个死键，全部是
`data.mantle.id.{0..19,default}`。它们是**活的**——`string_table.h` 的
`mantleName()` 运行时拼 `"data.mantle.id.%1"` 再调 `tr()`，正则只认字面量，
所以拼出来的 key 一律被判为无人引用。结论：`unused --strict` 在这棵树上是
**红的**（exit 1），`data.mantle.*` 清理前不要发版前用它门禁；要么给
`mantleName()` 的 key 加豁免，要么把前缀从字面量改成可识别的形态。

## 8. 加一种新语言要做什么

1. 建 `src/resources/i18n/<locale>/` 目录，四个域文件各一份
2. 跑 `i18n_key_parity.py` 到 PARITY OK
3. 在 `src/resources/resources.qrc` 列出新文件
4. 确认 `StringTable::load()` 的 locale 规范化认得这个 code
   （`core/locale_conf.h` 的 `canonicalLocale()`：`zh*` → `zh-CN`，
   其余一律 → `en-US`——加语言必须同时改这里，否则 cli 与 conf 都会被规范化掉）
5. 数据名表若要第三语言：改生成器补一列，并扩展 `isEnglish()` 的判定
