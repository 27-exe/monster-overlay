# Monster Overlay 本地化指南

> 面向贡献者：怎么加翻译、加一种语言、什么不该进翻译表。运行时事实以
> `src/core/string_table.h` 的注释为准，本文是规范，不是补丁说明。

## 1. 运行时机制

`mhw::StringTable`（`src/core/string_table.cpp`）是唯一入口：

- **每个 locale 是一个 qrc 目录**：`:/i18n/<locale>/<domain>.json`
- `load(locale)` 合并该目录下所有 `*.json` 成一张扁平表；同名 key 后者胜
- `tr(key)` 查不到时**返回 key 本身**——开发期直接暴露成点路径而不是渲染空白，比静默降级好修
- `locale.startsWith("en")` → `isEnglish()`；数据名表靠这一位选中英文列
- **热切换**：`load()` 可随时用另一个 locale 再调一次，表原地替换。缓存了字符串的 widget 必须
  重新查询：控制台走 `ControlPanel::retranslateUi()`，overlay 走 conf 轮询（`src/core/locale_sync.h`）

```cpp
mh::tr("console.rail.start_overlay")             // 取文案
mh::tr("ui.player_connected").arg(mem)           // 带 %1
```

## 2. 四个域文件

切分依据不是「哪个进程用」，而是**「谁负责重绘」**——这才是语言切换能生效的分组。

| 域文件 | 顶层前缀 | 内容 | 重放机制 |
|---|---|---|---|
| `overlay.json` | `ui.*` | overlay 面板 chrome（`ui.player_*` / `ui.monster_*` / `ui.zone_*` …） | 各面板 `paintPanel()` 每次重绘重新 `tr()` |
| `console.json` | `console.*` | 控制台 chrome | `ControlPanel::retranslateUi()` 重放注册表 |
| `reader.json` | `reader.*` | reader 状态 / 诊断上屏文案 | snapshot `status` 每 poll tick 自然刷新 |
| `data.json` | `data.*` | 数据名与演示数据（`data.mantle.*` / `data.demo.*`） | 别名每次 paint 重新查 |

每侧 locale 一套四文件；两侧 locale（`zh-CN` / `en-US`）共 8 个 JSON，逐域 key 数相等：
`console` 154 / `overlay` 45 / `reader` 144 / `data` 56，合计 399。新域只需在同目录再放一个
`<domain>.json`，运行时不用改。

## 3. Key 命名规范

三层 `<域>.<模块>.<语义>`，leaf 一律 snake_case：

```
overlay.panel.player.header        console.rail.start_overlay
data.mantle.id.3
```

- 目标三层；leaf 不缩写、不用 camelCase
- 占位符用 `%1..%N`，同一 key 的 zh/en **占位符集合必须相同**
- `_meta` 是给维护者的域说明，不进扁平表
- ❌ 不要塞非文案：字体族名、配置键、app 名（`"Monster Overlay"` 由
  `QApplication::setApplicationName()` 承担，不属于翻译表）

**注意历史形态**：`overlay.json` / `reader.json` 里有大量顶层单键（`ui.player_title`、
`reader.ptrace_denied`），是拆分前的遗留而非范例。按新规范写新键，不要为了凑三层去改已有 key。

## 4. 哪些文本进 i18n，哪些不进

| 类别 | 处置 | 例子 |
|---|---|---|
| UI chrome（按钮、标题、tooltip、状态行） | 必须进 JSON | `console.rail.start_overlay` |
| reader 上屏状态 / 诊断信息 | 必须进 JSON（`reader` 域） | `reader.ptrace_denied` |
| 演示数据（console 舞台预览种子） | 进 `data.json` 的 `data.demo.*` | `data.demo.ail.*` |
| **游戏数据名**（怪物 / 部位 / 异常 / 区域） | **留在 C++ 表**，双列 zh/en，运行时按 `isEnglish()` 选列 | `kRiseAilmentNames`、`zoneNameLocalized()` |
| 人工语义决策的别名 | 进 `data.json` | `data.mantle.*`、`data.demo.abn.*` |

**为什么数据名表不搬 JSON**：它们是 HunterPie Localization XML 生成的编译期 `constexpr` 表，
带 sha256 溯源链；量大、不可手译，搬进 JSON 只会丢掉编译期校验。需要第三语言时按同一生成器补一列。

**判断一个 tag 归属的方法**：问「这是 UI 结构的一部分，还是这个数据的固有属性？」前者进
`overlay` / `console` / `reader` 域走 `tr()`，后者留在数据表按列选。

## 5. 兜底策略

**UI 层：代码里不允许兜底**（no fallback in code）。key 必然存在（门禁保证 zh/en 对齐），
所以 UI 层的 `kFallback` 数组是死码。更要紧的是它会**藏 bug**：`static const QStringList`
会把首次使用的语言冻结，于是「切了语言但标签不变」这类缺陷永远不被发现。UI 层一律直接 `tr()`。

数据层允许成对出现：`kFoo` 表的 `{name, nameEn}` 是数据不是文案兜底，en 列为空时读 zh，
是「数据缺英文译名」的合理降级。

唯一例外是拿 `tr()` 结果做相等比较的哨兵（`src/core/string_table.h` 的 `mantleName()`、
`src/core/game_capabilities.cpp` 的 `gameDisplayName()`、`src/ui/hud_canvas.cpp` 的
`panelName()` / `cornerLabel()`）。它们靠「返回值 == key」判定缺失，因此必须自带一个 ASCII
兜底；改动这四处时必须连 JSON 侧一起看。

## 6. 游戏显示名也是 i18n key

控制台 GAME 列与自动检测徽标上的游戏名不在 UI 里做分支，而是 `src/core/game_capabilities.cpp`
里 traits 表的一列 `displayNameKey`。JSON 侧 `console.game.{world,rise}` 照常按 §4 翻译，
`gameDisplayName()` 先 `tr(key)`、key 缺失才回落同表的 ASCII 列。加一款游戏是在这张表**加一行**。

## 7. 门禁

`scripts/i18n_gate.py` 是统一入口，已接入 ctest：`python3 scripts/i18n_gate.py` 跑全部三个，
`--strict` 把死键也当作失败。

| 脚本 | 校验 |
|---|---|
| `scripts/i18n_check_tr_keys.py` | 代码里所有 key 在每个 locale 的 JSON 中都有定义 |
| `scripts/i18n_key_parity.py` | zh/en key 集合一致（含 `_meta`、占位符数量） |
| `scripts/i18n_unused_keys.py` | 报告没人引用的死键 |

`unused` 默认只报告、不拦提交：一个没人引用的 key 玩家看不见，拿它当门禁会把一次 cosmetic
清理变成每次提交的红灯。`--strict` 留给发版前自查。

## 8. 加一种新语言

1. 建 `src/resources/i18n/<locale>/` 目录，四个域文件各一份
2. 跑 `i18n_key_parity.py` 到 PARITY OK
3. 在 `src/resources/resources.qrc` 列出 4 个新文件
4. 确认 `StringTable::load()` 认得这个 code：`src/core/locale_conf.h` 的 `canonicalLocale()`
   目前只认 `zh*` → `zh-CN`，其余一律 → `en-US`，**加语言必须同时改这里**，否则 cli 与 conf
   都会被规范化掉
5. 数据名表若要第三语言：改 HunterPie 生成器补一列，并扩展 `isEnglish()` 的判定
6. 手动过一遍 UI：切语言后每块面板都确认重新取了一次 `tr()`
